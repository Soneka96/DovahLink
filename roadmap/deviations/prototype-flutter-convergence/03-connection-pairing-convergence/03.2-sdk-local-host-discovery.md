# 03.2 — SDK Local Host Discovery

**Status:** Complete

## Outcome

Added SDK-owned local discovery that returns Host candidates with identity, name, and endpoint
information.

## Why it exists

The prototype's Host-selection surface needed real candidates rather than a fixed or fabricated Host
card.

## Scope

Discovery is local/loopback only and uses an isolated transient connection. It reports a candidate;
it does not establish trust or mutate persisted Known Host state.

## Non-goals

- No LAN, mDNS/DNS-SD, or remote discovery was implemented by this slice.
- Discovery does not authorize, authenticate, or trust a candidate.

## Dependencies / authority

The SDK owns reusable discovery behavior. Host identity remains defined by
[03.1](03.1-host-identity.md) and the
[identity and transport security architecture](../../../../ai/context/security/identity-and-transport.md).

## Acceptance criteria

- Local discovery returns Host candidates with identity/name/endpoint information.
- Discovery uses a transient isolated connection and closes it when discovery completes.
- Discovery alone does not change Known Host persistence or trust.

## History

[PR #98 — Feature/3.2 SDK local Host discovery](https://github.com/Soneka96/DovahLink/pull/98) merged
local SDK discovery. The PR explicitly did not add LAN or mDNS discovery.
