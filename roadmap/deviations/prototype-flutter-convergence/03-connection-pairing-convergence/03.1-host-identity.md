# 03.1 — Host Identity Contract

**Status:** Complete

## Outcome

Introduced a stable Host installation identity and separated it from mutable Host name metadata and
the endpoint used to reach it.

## Why it exists

Prototype connection cards and Host selection needed a truthful way to distinguish a Host from its
current computer name or network location.

## Scope

The delivered contract defines `hostId` as the stable logical Host installation identity, distinct
from hostname, endpoint, Steam ID, and `stateAuthorityId`; `hostName` is mutable OS-derived metadata;
and endpoint is routing information. Host identity metadata is exposed through `hello_ack`.

## Non-goals

- It did not make a hostname or endpoint an identity.
- It did not implement LAN discovery or choose a production initial-pairing protocol.
- This record does not restate the full identity/security architecture.

## Dependencies / authority

See [ARCHITECTURE.md](../../../../ARCHITECTURE.md) and the
[identity and transport security architecture](../../../../ai/context/security/identity-and-transport.md)
for the current identity contract.

## Acceptance criteria

- `hostId` remains stable across normal Host restarts and machine rename.
- `hostName` may change and the endpoint may change without changing Host identity.
- Client presentation can identify a specific Host without treating location or display name as
  identity.
