# 03.9 — Settings / Device Name

**Status:** Paused / requires re-planning

## Outcome

The original goal was to converge Settings with prototype presentation and provide a companion name
for product-facing identity. This step is not claimed complete.

## Why it exists

The prototype shows the companion as a user-recognizable device, while display preference, OS name
lookup, and reusable Client identity have different owners.

## Scope

Original ownership direction:

- App: user display-name override and presentation preference.
- Platform: OS device/computer-name lookup.
- SDK: reusable logical Client identity and security semantics.

## Non-goals

- Settings must not make Flutter a security or trust authority.
- This record does not freeze the final settings layout, identity field, or persistence model.

## Dependencies / authority

Use the current Flutter and SDK boundaries plus the
[identity and transport security architecture](../../../../ai/context/security/identity-and-transport.md).

## Acceptance criteria

**Original intent, not a current implementation contract:** user-controlled presentation preferences
remain distinct from platform metadata and SDK-owned logical identity.

## History

Device-name behavior was part of the prototype convergence sequence after pairing and connection
surfaces were being integrated.

## Current disposition

Paused / requires re-planning.

## Next action

Re-plan the setting and fallback behavior without moving identity or security decisions into Flutter.
