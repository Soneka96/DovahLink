# Concept 01.2b -- Internal code, tests, and tooling terminology

**Status:** pending

**Covers:** No `SOURCE.md` requirement ID -- part of the D4 vocabulary-normalization
programme. See `DIVERGENCES.md` D4.

**Depends on:** Concept 01.2a merged to `main` (internal renames should read against
already-corrected active documentation, not documentation still describing "Bridge"
as current).

## Why this is a stable concept

This is a behavior-neutral semantic rename of non-public, non-wire implementation
*identifiers* -- distinct from `01.2a`'s prose/comment-text scope (which, per its own
scope rule, can touch a source file's comment text but never its identifiers) and
from `01.3a`/`01.3b`/`01.3c`'s public-vocabulary decision and cutover. It must
complete before `01.3a` so the design gate reasons about a codebase whose internal
names already agree with their actual owner.

## Goal

Rename stale non-public/non-wire "Bridge" terminology -- both internal implementation
identifiers and human-readable text that names the retired Bridge concept -- to Host,
Adapter, or DovahLink terminology, whichever is the actual current semantic owner.
Behavior-neutral: no functional, protocol, or wire-contract change; only names and
wording change, even where that wording is user- or consumer-observable (UI text, log
lines, diagnostic messages). See CONTEXT.md's "Concept 01.2b scope-boundary
correction" and its later reversal for the history of this boundary.

## Boundary against 01.2a

Per `01.2a`'s scope rule: a comment that merely narrates general current-architecture
behavior belongs to `01.2a`, even inside a source file this concept otherwise owns.
A comment or identifier that *cannot be fixed independently of the Bridge-named thing
it describes* -- the two examples below -- belongs here instead. Do not re-triage
either direction without updating both concept files.

## Design

- Choose the replacement by semantic owner, per D4/the source brief:
  old name says Bridge, actual owner is Host -> Host terminology; actual owner is
  Adapter -> Adapter terminology; spans the product -> DovahLink terminology.
- `app/lib/features/connection/domain/entities/bridge.entity.dart` (`BridgeEntity`,
  "A DovahLink Bridge a client can select and connect or pair with") and its
  dependents -- `bridge_list.screen.dart`, `bridge_list_screen.viewmodel.dart`,
  `connection.injection_container.dart`, and their test files -- model "a DovahLink
  instance to connect to." This is internal app naming (not a wire/serialized
  contract; confirm this during this concept's own inventory before treating it as
  such), so it is in scope here: rename by actual current meaning, verified against
  `ai/context/flutter/architecture.md`'s domain-naming conventions rather than
  guessed.
- `adapter/runtime/adapter_task_marshaller.hpp`'s doc comment still cites
  `IBridgeCallbackRegistry`, a name Concept 01 already removed from
  `ai/context/skse/cpp-style.md` when it replaced that convention's worked example.
  Update the comment to cite the current example (`IAdapterPairingNotificationSink`)
  instead.
- Audit `tooling/**` (`test_repository_consistency.py`,
  `validate_protocol_fixtures.py`, `test_validate_protocol_fixtures.py`,
  `test_format_staged.py`, `run-local-ci.ps1`) for internal-only naming; do not touch
  any assertion covering a public/wire field (defer to `01.3a`-`01.3c`).

## Public boundary exclusion

Do not change in this concept: `bridgeVersion`, `bridgeInstanceId`, JSON keys,
canonical protocol field names, wire fixtures, persisted file formats,
environment/configuration names with external meaning, CLI names/options, public
error codes, public SDK API identifiers a consumer compiles against, or anything
whose rename could break a consumer's compile-time or wire-level contract.

Human-readable text -- UI labels, log messages, diagnostic/exception message
strings, test descriptions, and comments describing current architecture -- is in
scope even where a consumer can observe it (logs, error UI, test output), unless that
exact text is itself explicitly documented or consumed as a stable external contract.
This is narrower than "nothing observable changes": observability alone is not an
exclusion, only a documented/consumed external contract is. If uncertain whether
something is public/contractual, treat it as public and defer it to `01.3a`.

## No semantic refactors

Do not combine the rename with DI/lifetime changes, `AdapterRuntime` work, class
extraction, queue redesign, protocol redesign, a documentation sweep, or performance
optimization. If a stale name exposes a deeper architectural defect, record it
separately; do not fix it here.

## Files this concept may change

Exactly the category-B file set this concept's own inventory pass identifies, at
minimum: `app/lib/features/connection/**` and its test counterparts (the `BridgeEntity`
cluster), `adapter/runtime/adapter_task_marshaller.hpp`, and any other internal
identifier/comment/log-label found during inventory in `host/**`, `adapter/**`,
`sdk/**`, `app/**`, `integration/**`, `tooling/**` that is confirmed non-public.

## Tests / proof obligations

- Category-B inventory is empty after the PR, except explicit approved exceptions.
- Code behavior is identical; all affected build/test suites pass.
- No category-C/D occurrence was accidentally changed; no public serialized shape
  changed; no composition/lifetime change.
- Diff is predominantly renames and direct reference updates.

## Non-goals

- Any public wire/vocabulary decision or change -- `01.3a`/`01.3b`/`01.3c`.
- Documentation-only fixes -- `01.2a` (already done, merged before this starts).
- Any composition/lifetime/architecture change.

## PR-size gate

Expected changed files: ~25-35 (see `01.2a`'s inventory estimate; category B).
Hard stop: 100. Re-plan threshold: >80.

If >80 files are predicted, split by ownership boundary, not arbitrary size --
preferred order: `01.2b-1` Host + Adapter internal implementation/tests,
`01.2b-2` SDK/App/integration/tooling internal terminology. Each split PR must
independently compile/test.

## Completion criteria and evidence

- Category-B inventory empty (or explicit approved exceptions recorded).
- Full affected build/test suites green; no public/wire change.
- `PLAN.md` status table updated with this concept's PR number, marked `Complete`
