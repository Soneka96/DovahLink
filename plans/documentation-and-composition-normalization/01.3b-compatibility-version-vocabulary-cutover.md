**Status:** pending

**Covers:** No `SOURCE.md` requirement ID -- part of the D4 vocabulary-normalization
programme. See `DIVERGENCES.md` D4. This concept, and `01.3c`, are the package's only
concepts permitted to change public/wire protocol behavior, and only to the exact
extent `01.3a` decides -- the approved exception to the package-wide "no protocol
change" invariant (`PLAN.md` section 3).

as an opportunity to also address anything not in that decision's vocabulary table.

## No unrelated protocol work

Do not alter message framing, auth, pairing, session IDs, state subscription logic,
capabilities, instance identity (`01.3c`'s job), or the protocol generation/
versioning model beyond the approved `01.3a` decision.

## Files this concept may change

Exactly the files `01.3a`'s vocabulary table and blast-radius enumeration name,
verified by this concept's own re-run inventory: `protocol/schema/README.md`, the
~3 `bridgeVersion`-carrying fixtures, the Host hello/hello_ack model and codec (and
their tests), the SDK's corresponding model (and its test), affected app consumers,
`ai/context/protocol/compatibility.md`, and any tooling/tests asserting the old field
name.

## Tests / proof obligations

- `01.3a`'s mapping is implemented exactly.
- Host emits the decided version value from the decided authority.
- SDK validates the decided field before normal traffic, per the compatibility
  contract.
- Too-old/too-new behavior remains explicit and tested.
- Canonical schema, fixtures, implementation, SDK, and docs agree.
- No active category-D `bridgeVersion` terminology remains except intentional
  historical/frozen references.
- Full affected tests green.

## Non-goals

- Public instance identity -- `01.3c`.
- Any decision not already made in `01.3a` -- if a gap is found, stop and return to
  `01.3a` rather than deciding it here.

## PR-size gate

Expected changed files: ~10-15 (small -- `bridgeVersion` appears in only 3 of
`protocol/fixtures/`'s JSON fixtures, unlike `bridgeInstanceId`'s 57).
Hard stop: 100. Re-plan threshold: >80.

If the atomic migration cannot fit within the file limit, stop for maintainer review.
Do not invent dual-field/alias behavior.
