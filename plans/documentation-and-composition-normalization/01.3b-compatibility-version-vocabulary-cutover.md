## Tests / proof obligations

- `01.3a`'s mapping is implemented exactly.
- Host emits the decided version value from the decided authority.
- This concept renames the compatibility-authority wire field and vocabulary and
  preserves current behavior exactly: the SDK decodes `hostVersion` the same
  unvalidated, pass-through way it decoded `bridgeVersion` before this concept. SDK-side
  supported-range validation and too-old/too-new rejection do not exist anywhere in this
  codebase today (confirmed repo-wide, `main` included) and are not decided by `01.3a`
  -- they are `roadmap/05-dart-client-sdk-foundation.md`'s own documented-undone Phase 5
  scope (`sdk/README.md`'s "Phase 5's remaining scope -- Host-version compatibility
  detection ... is undone"). Building that enforcement here would be new protocol
  implementation this concept's own scope and `AGENTS.md`'s non-negotiable rules forbid
  ("do not add ... protocol implementation until the maintainer explicitly requests
  that feature"; "any decision not already made in `01.3a` -- stop and return to
  `01.3a`" per this file's own Non-goals below). `01.3a`'s Section A sentence saying the
  SDK "continues" to declare a range and that the mechanism is "unchanged from today" is
  factually imprecise -- no such mechanism exists today to leave unchanged. This is
  recorded and resolved as `DIVERGENCES.md` D5, not asserted here on this file's own
  authority: `01.3a`'s merged text is not edited; D5 records that its Section A
  describes the compatibility *authority* (which this concept implements) rather than
  an already-built enforcement *mechanism* (which remains Stage 5's undone scope).
- Canonical schema, fixtures, implementation, SDK, and docs agree.
- No active category-D `bridgeVersion` terminology remains except intentional
  historical/frozen references.
- Full affected tests green.
