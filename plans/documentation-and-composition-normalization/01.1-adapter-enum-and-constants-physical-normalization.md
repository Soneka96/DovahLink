# Concept 01.1 -- Adapter enum and constants physical normalization

**Status:** pending

**Covers:** No `SOURCE.md` requirement ID -- this concept did not exist in the original
five-issue decomposition. It exists to make `adapter/`'s actual source layout conform
to the enum/constants convention Concept 01 wrote into
`ai/context/skse/cpp-style.md` (one project-wide `adapter/enums.hpp` and one
project-wide `adapter/constants.hpp`, mirroring `ai/context/dotnet/csharp-style.md`'s
per-project `Enums.cs`/`Constants.cs`). See `DIVERGENCES.md` D2 for why this concept
was inserted and where it sits in the sequence.

**Depends on:** Concept 01 merged to `main` (the convention this concept implements
must already be the documented, current rule before source is moved to match it).

## Why this is a stable concept

This is a purely mechanical physical-layout change -- move one file, gather scattered
constants into one file, fix every include -- with no design decisions left open by the
time it starts (Concept 01 already settled the target shape). It is deliberately not
folded into Concept 03 (Adapter runtime composition): Concept 03's job is ownership and
composition of the process-lifetime object graph, a different concern from where enum
and constant *declarations* physically live. Keeping them separate means Concept 03
starts from an already-normalized source layout instead of doing this cleanup as an
unplanned side quest.

## Design

- Move `adapter/ipc/ipc_enums.hpp` to `adapter/enums.hpp`. Every enum currently declared
  in it (`IpcMessageKind`, `IpcCloseReason`, `IpcRejectReason`, `IpcHelloRejectReason`,
  `PairingDisplayMode`, `TrustAdminOperation`, `TrustAdminListScope`) keeps its existing
  namespace (`dovahlink::adapter::ipc`) -- the file moves, the namespaces do not
  flatten. Group them under a `// ---- IPC ----` banner as the file's first (and
  currently only) section, per `cpp-style.md`'s rule.
- Update every `#include "ipc/ipc_enums.hpp"` to `#include "enums.hpp"` (or the
  project's actual include-path convention for a file at `adapter/`'s root -- match
  whatever `adapter/CMakeLists.txt`'s existing include-directory setup expects). The
  verified current includers are `ipc/adapter_ipc_session.hpp`,
  `ipc/adapter_pairing_notification_sink.hpp`, `ipc/ipc_close_message.hpp`,
  `ipc/ipc_frame_codec.hpp`, `ipc/ipc_hello_ack_message.hpp`,
  `ipc/ipc_pairing_display_message.hpp`, `ipc/ipc_reject_message.hpp`,
  `ipc/ipc_trust_admin_request_message.hpp`, and
  `papyrus/commonlib_adapter_trust_admin_papyrus_adapter.cpp` -- re-verify this list at
  implementation time rather than trusting it blindly, since new includers may have
  been added since.
- Create `adapter/constants.hpp` and move every module's cross-cutting constant values
  into it (verified current per-module files at the time of Concept 01:
  `capture/adapter_capture_constants.hpp`, `ipc/ipc_constants.hpp`,
  `process/adapter_host_constants.hpp`, `runtime/adapter_runtime_constants.hpp`;
  re-verify at implementation time), each kept in its own domain namespace and grouped
  under its own `// ---- <Area> ----` banner, mirroring the enum file's shape. Update
  every includer accordingly.
- Verify `adapter/CMakeLists.txt` at implementation time: it currently declares no
  per-header target-sources list and exposes `${CMAKE_CURRENT_SOURCE_DIR}` as a plain
  include root (headers aren't individually registered), so this move likely needs no
  CMake change at all. Update it only if that verification finds an actual path
  reference or build declaration that must change (for example one of the
  `DOVAHLINK_ADAPTER_*_DIR`/`*_SOURCE_FILE` compile definitions the test target
  passes) -- do not make a no-op/ceremonial edit merely because a file moved.
- Update every Adapter test that includes either the old per-module files or asserts
  their paths.

## Files this concept may change

- `adapter/enums.hpp` (new), `adapter/constants.hpp` (new)
- `adapter/ipc/ipc_enums.hpp` (removed), and each verified per-module `constants.hpp`
  (removed)
- Every file listed above as a current includer, plus any other includer found during
  implementation
- `adapter/CMakeLists.txt`, only if verification finds an actual reference that needs
  updating -- expected to need no change, per the Design section above.
- `adapter/tests/**` files referencing any moved declaration or path
- `ai/context/skse/cpp-style.md`: remove the "pending a physical normalization" /
  "pending the same physical normalization" framing once the move is real, since the
  rule then describes current fact rather than a target state
- `tooling/test_repository_consistency.py`: update the enum/constants assertions to
  match the completed move

## Tests / proof obligations

- Full Adapter/C++ test suite green, identical behavior to before the move -- this is a
  pure file/namespace-location change with no logic edits.
- Build succeeds via the project's normal CMake configure/build commands.
- `tooling/test_repository_consistency.py` green, including the updated cpp-style.md
  assertions.

## Non-goals

- Any change to `AdapterRuntime`, process-lifetime composition, or ownership --
  Concept 03's responsibility, done afterward on this now-normalized layout.
- Any change to enum or constant *values* -- this is a location move only.
- Consolidating Host-side (C#) enums/constants -- `csharp-style.md`'s per-project
  `Enums.cs`/`Constants.cs` convention is already followed; nothing to normalize there.
- Renaming any enum or constant.
