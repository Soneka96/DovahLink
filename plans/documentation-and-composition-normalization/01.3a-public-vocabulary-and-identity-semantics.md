# Concept 01.3a -- Public vocabulary and identity/version semantics decision

**Status:** pending

**Covers:** No `SOURCE.md` requirement ID -- part of the D4 vocabulary-normalization
programme. See `DIVERGENCES.md` D4.

**Depends on:** Concept 01.2b merged to `main`.

## This is a design-only gate

**No wire implementation changes in this PR.** Its job is to resolve semantics before
anyone performs a public rename. `protocol/schema/README.md` already treats
`bridgeVersion` as a legacy wire-field name carrying the DovahLink product release
version; `ai/context/protocol/compatibility.md` already says the Host release
replaces the retired Bridge release as compatibility authority, and separately defers
the public authoritative-process instance identifier represented by the legacy
`bridgeInstanceId` field while explicitly prohibiting substituting `adapterInstanceId`,
a PID, a port, or a connection/session ID for it. This concept converts those
transitional notes into one complete, internally consistent decision.

## Mandatory decisions

### A. Compatibility authority

Decide exactly: what release/version a client compares against; whether the
authority is the Host release, the whole DovahLink product release, or another
existing source; the repository file/metadata source of truth; how the SDK declares
its supported range; too-old/too-new peer behavior; and confirm this remains a
release-compatibility check rather than a new protocol-generation number (the
protocol-generation model was already retired once, per
`ai/context/protocol/compatibility.md`'s history -- do not reintroduce it).

### B. Canonical version vocabulary

Decide exact names for: the wire field currently named `bridgeVersion`; the
Host-side property/model name; the Dart SDK/public model name; tests/fixtures; docs
terminology. Base the decision on semantics (does it carry a Host-only version or a
whole-product version?), not aesthetics -- do not choose `hostVersion` if it actually
carries a whole-product version, and do not choose `dovahLinkVersion` if
compatibility is explicitly owned by the Host release.

### C. Public authoritative-process instance identity

Decide whether the public protocol exposes an instance identifier at all. If yes,
define: canonical name; owner; creation point; exact lifetime; stability across
client reconnects; behavior across Host restart; behavior on Adapter reconnect/
restart; relation to `playContextId`, `sessionId`, transport `ConnectionId`, and
`adapterInstanceId`; whether it may ever be null after Host startup; failure behavior
if generation fails; whether every Host-originated envelope carries it; how clients
cache/compare it; how state revision identity is scoped. It must not be a disguised
alias for `adapterInstanceId`, a PID, a port, a hostname, a socket, a connection ID,
or a session ID.

### D. State and cache invalidation

Define the exact tuple determining whether cached authoritative state is from the
same authority/lifetime. The current tuple is
`(bridgeInstanceId, playContextId, stateArea)`
(`protocol/schema/README.md`'s "Registered state areas" section) -- state its exact
replacement and why, covering: same Host + reconnect; same Host + new session; same
Host + new play context; Host restart; Adapter reconnect; multiple concurrent
clients.

### E. Migration policy

State: is this intentionally breaking in the pre-release product (per
`ai/context/common.md`'s "Pre-release compatibility" -- the default answer is yes);
are old field names removed atomically; are aliases forbidden (default: yes); is any
temporary compatibility required (default: no); what SDK supported-range change is
required; how unsupported old clients fail. Default: do not invent compatibility
shims.

### F. Exact old -> new vocabulary table

End the design PR with an explicit mapping, at minimum:

| Current | Meaning | Decision | Replacement | Implementation concept |
| --- | --- | --- | --- | --- |
| `bridgeVersion` | compatibility release | rename/cutover | `<decided>` | 01.3b |
| `bridgeInstanceId` | public authority lifetime | rename/activate/remove | `<decided>` | 01.3c |
| `adapterInstanceId` | native Adapter lifetime | keep | unchanged | none |
| Bridge compatibility range wording | old compatibility terminology | cutover | `<decided>` | 01.3b |

No implementation concept (`01.3b`/`01.3c`) starts while any row is "TBD."
